# 🤖 Telegram Content Aggregator Bot

ربات تجمیع‌کننده محتوای تلگرام پیشرفته، مبتنی بر **Cloudflare Workers** + **D1** + **Workers AI**.

رباتی که کانال‌های عمومی تلگرامی را از طریق نسخه وب (`t.me/s/`) می‌خواند، محتوای جدید را بر اساس حالت‌های مختلف فیلتر کرده و به گروه/تاپیک/کانال مقصد شما ارسال می‌کند. کاملاً رایگان، بدون سرور و با بهینه‌سازی برای جلوگیری از خطای CPU کلادفلر.

> **🆕 نسخه v4:** هش‌های ضدتکراری از KV به D1 منتقل شدند — پشتیبانی از **۵۰۰+ منبع** در پلن رایگان. سیستم دسترسی ادمین، Workers AI، گزارش روزانه و پنل مدیریت کامل.

## ✨ ویژگی‌ها

### 🤖 سیستم اسکن و جمع‌آوری محتوا
- ✅ خواندن کانال‌های عمومی از طریق `t.me/s/` با سرعت بالا
- ✅ تکنیک Pagination — در هر اجرای Cron فقط **یک منبع** بررسی می‌شود (حلقه‌ای Round-Robin)
- ✅ تشخیص نوع رسانه (عکس، ویدیو، فایل، صوت، استیکر، نظرسنجی، متن)
- ✅ تشخیص تعداد بازدید پست‌ها
- ✅ سیستم ضدتکراری با **SHA-256** ذخیره‌شده در **D1** (نه KV) به مدت **۷ روز** — پشتیبانی از ۵۰۰+ منبع بدون محدودیت

### 🎯 حالت‌های اسکن (Scan Modes)
| حالت | توضیح |
|------|--------|
| `forward` | ارسال تمام پست‌های جدید بدون فیلتر |
| `deep` | فیلتر بر اساس کلیدواژه مثبت + منفی، با پشتیبانی از کلمات مرکب |
| `viral` | ارسال پست‌هایی که بازدیدشان از آستانه تعیین‌شده بیشتر است |

**حالت deep:**
- `every` روشن → پست باید **همه** کلیدواژه‌های مثبت را داشته باشد (AND)
- پیش‌فرض → کافی است **حداقل یکی** از کلیدواژه‌ها موجود باشد (OR)
- کلمات منفی → اگر حتی یکی در پست باشد، محتوا ارسال نمی‌شود (حتی اگر کلیدواژه مثبت داشته باشد)

### مرحله ۱: ساخت ربات در تلگرام

1. در تلگرام به **[@BotFather](https://t.me/BotFather)** بروید.
2. دستور `/newbot` را بفرستید.
3. یک **نام** برای ربات انتخاب کنید (مثلاً: Content Aggregator).
4. یک **username** انتخاب کنید که به `bot` ختم شود (مثلاً: `my_aggregator_bot`).
5. BotFather یک **توکن** به شما می‌دهد:
   ```
   123456789:ABCdefGHIjklMNOpqrsTUVwxyz
   ```
   این توکن را ذخیره کنید.
6. **آیدی عددی خود** را بگیرید: به **[@userinfobot](https://t.me/userinfobot)** پیام بدهید تا آیدی عددی‌تان را بدهد (مثلاً: `987654321`). این آیدی، ادمین اصلی ربات خواهد بود.
7. ربات را به گروه/کانال مقصد **افزوده و ادمین** کنید (با حداقل دسترسی ارسال پیام).

---

### مرحله ۲: ایجاد دیتابیس D1

```bash
wrangler d1 create aggregator
```

خروجی چیزی شبیه این خواهد بود:
```
✅ Successfully created DB 'aggregator'
database_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
```

`database_id` را کپی کنید.

سپس اسکیمای دیتابیس را اعمال کنید:
```bash
wrangler d1 execute aggregator --file=./schema.sql
```

---

### مرحله ۳: ایجاد فضای KV

```bash
wrangler kv namespace create AGGREGATOR
```

خروجی:
```
✅ Successfully created KV namespace "AGGREGATOR"
id = "yyyyyyyyyyyyyyyyyyyyyyyy"
```

`id` را کپی کنید.

---

### مرحله ۴: پیکربندی Wrangler

فایل `wrangler.toml.example` را به `wrangler.toml` کپی کنید:

```bash
cp wrangler.toml.example wrangler.toml
```

و مقادیر زیر را جایگزین کنید:

| متغیر | نوع | توضیح |
|-------|-----|--------|
| `MAIN_ADMIN_ID` | var (متغیر عمومی) | آیدی عددی ادمین اصلی تلگرام |
| `BOT_TOKEN` | secret (محرمانه) | توکن ربات از BotFather |
| `PANEL_PASSWORD` | secret (محرمانه) | رمز عبور پنل تحت وب |
| `DB` | binding D1 | اتصال به دیتابیس `aggregator` |
| `KV` | binding KV | اتصال به فضای KV |
| `crons` | trigger | `*/2 * * * *` (هر ۲ دقیقه) |

نمونه `wrangler.toml` نهایی:

```toml
name = "telegram-aggregator"
main = "worker.js"
compatibility_date = "2024-09-23"

[triggers]
crons = ["*/2 * * * *"]

[vars]
MAIN_ADMIN_ID = "987654321"

[[d1_databases]]
binding = "DB"
database_name = "aggregator"
database_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"

[[kv_namespaces]]
binding = "KV"
id = "yyyyyyyyyyyyyyyyyyyyyyyy"
```

### مرحله ۵.۵: غیرفعال کردن Privacy Mode (مهم!)

به‌صورت پیش‌فرض، ربات‌های تلگرام در گروه‌ها **Privacy Mode** فعال دارند — یعنی فقط پیام‌های شروع‌شده با `/` (دستورات) و ریپلای‌ها به ربات را دریافت می‌کنند. این یعنی وقتی ربات می‌پرسد «کلیدواژه‌ها را بفرستید» و شما متن را در گروه می‌نویسید، **ربات آن را دریافت نمی‌کند**.

برای غیرفعال کردن:

1. به **[@BotFather](https://t.me/BotFather)** بروید
2. دستور `/setprivacy` را بفرستید
3. ربات خود را انتخاب کنید
4. گزینه **Disable** را انتخاب کنید

> ⚠️ این کار را **قبل** از افزودن ربات به گروه انجام دهید. اگر ربات قبلاً اضافه شده، بعد از غیرفعال کردن Privacy Mode، ربات را از گروه حذف و دوباره اضافه کنید.

> 💡 اگر نمی‌خواهید Privacy Mode را غیرفعال کنید، ربات از `force_reply` استفاده می‌کند — یعنی برای هر سؤال، باید روی پیام ربات **Reply** بزنید و پاسخ را بنویسید. اما غیرفعال کردن Privacy Mode تجربه بهتری می‌دهد.

برای اینکه وقتی در چات تلگرام `/` را تایپ می‌کنید، منوی پیشنهادی دستورات ظاهر شود، یک‌بار آدرس زیر را در مرورگر باز کنید:

```
https://telegram-aggregator.<your-subdomain>.workers.dev/setup-commands
```

باید پاسخ `✅ ۱۶ دستور در تلگرام ثبت شد` را ببینید. حالا در چات ربات `/` را تایپ کنید — لیست دستورات به‌صورت منوی کشویی نمایش داده می‌شود.

> 💡 این کار فقط یک‌بار لازم است. اگر دستور جدیدی اضافه کردید، دوباره این آدرس را باز کنید.

### مرحله ۸: دیپلوی پنل روی Cloudflare Pages

1. به داشبورد Cloudflare → **Workers & Pages** → **Create application** → **Pages** بروید.
2. روش **Direct Upload** را انتخاب کنید.
3. پوشه `panel/` را آپلود کنید (فقط شامل `index.html`).
4. نام پروژه را بگذارید: `aggregator-panel`.
5. پس از دیپلوی، آدرس پنل:
   ```
   https://aggregator-panel.<your-subdomain>.pages.dev
   ```

> 💡 **نکته:** هنگام ورود به پنل، آدرس ورکر خود را در فیلد «آدرس Worker» وارد کنید.

### مرحله ۹: تست ربات

1. در تلگرام ربات خود را باز کنید و `/start` بفرستید.
2. باید ری‌اکشن 🫡 دریافت کنید و منوی اصلی نمایش داده شود.
3. با دکمه **➕ افزودن منبع** اولین کانال را اضافه کنید.
4. چند دقیقه صبر کنید تا Cron اجرا شود، یا از دستور `/scan` برای اسکن فوری استفاده کنید.

## ⏱ تنظیم Cron

در فایل `wrangler.toml`:

```toml
[triggers]
crons = ["*/2 * * * *"]
```

**نحوه کار:** هر ۲ دقیقه، ورکر یک منبع را بررسی می‌کند (به ترتیب از منبع ۱ تا آخر، سپس دوباره از اول). این کار از خطای `Exceeded CPU` جلوگیری می‌کند.

> پلن رایگان کلادفلر اجازه می‌دهد Cron با حداقل فاصله ۱ دقیقه اجرا شود.

## 🔧 عیب‌یابی

### ربات جواب نمی‌دهد
1. بررسی کنید وب‌هوک تنظیم شده: `curl "https://api.telegram.org/bot<TOKEN>/getWebhookInfo"`
2. مطمئن شوید آیدی شما با `MAIN_ADMIN_ID` یکی است.
3. لاگ‌های ورکر را ببینید: `wrangler tail`

### خطای Exceeded CPU
- این خطا نباید رخ دهد چون هر Cron فقط یک منبع را بررسی می‌کند.
- اگر رخ داد، فاصله Cron را به `*/3 * * * *` افزایش دهید.

### پست‌های تکراری ارسال می‌شود
- هش‌ها ۷ روز در KV نگه داشته می‌شوند. پس از ۷ روز ممکن است تکرار رخ دهد.
- برای پاکسازی دستی: `wrangler kv key list --binding=KV` و حذف کلیدهای `hash:`.

### پنل باز نمی‌شود / خطای "Failed to fetch"
این خطا تقریباً همیشه به یکی از دلایل زیر است:

**۱. آدرس ورکر اشتباه یا با `/` اضافه در انتها**
- ❌ اشتباه: `https://my-worker.workers.dev/panel/` یا `my-worker.workers.dev`
- ✅ درست: `https://my-worker.workers.dev` (با `https://` و بدون اسلش انتهایی)

**۲. ورکر هنوز دیپلوی نشده**
- با مرورگر آدرس `https://<your-worker>.workers.dev/` را باز کنید — باید `{"ok":true,...}` ببینید.
- اگر ۴۰۴ یا خطا دیدید، `wrangler deploy` را اجرا کنید.

**۳. مشکل CORS با credentials (شایع‌ترین علت)**
اگر در Console مرورگر خطایی مثل این می‌بینید:
```
Access to fetch ... blocked by CORS policy:
The value of the 'Access-Control-Allow-Origin' header in the response must not be '*'
when the request's credentials mode is 'include'.
```
این یعنی ورکر شما نسخه قدیمی است که `Access-Control-Allow-Origin: *` را با `credentials: true` ترکیب می‌کرد — که طبق استاندارد CORS **ممنوع** است. ورکر فعلی (نسخه v2.4+) این مشکل را رفع کرده: به جای `*`، Origin دقیق درخواست‌کننده را برمی‌گرداند.

**راه‌حل:** فایل `worker.js` را با نسخه جدید جایگزین کنید و `wrangler deploy` اجرا کنید.

**۴. کوکی سشن ست نمی‌شود (ورود موفق اما بلافاصله لاگ‌اوت)**
- کوکی `SameSite=None; Secure` فقط روی **HTTPS** کار می‌کند. آدرس ورکر Cloudflare همیشه HTTPS است، پس مشکلی نیست.
- اگر لوکال تست می‌کنید (روی `http://localhost`)، کوکی ست نمی‌شود. همیشه روی ورکر دیپلوی‌شده تست کنید.
- مطمئن شوید آدرس پنل (Pages) و ورکر روی دامنه‌های متفاوت هستند (cross-site) — این حالت پشتیبانی می‌شود.

## 🔄 آپدیت ربات (نسخه v3 — با Workers AI)

اگر نسخه قبلی ربات را نصب کرده‌اید، برای آپدیت به v3 این مراحل را دنبال کنید:

### مرحله ۱: مایگریشن دیتابیس

ستون‌های جدید اضافه شده‌اند. این دستورات را اجرا کنید:

```bash
wrangler d1 execute aggregator --command "ALTER TABLE sources ADD COLUMN topic TEXT DEFAULT '';"
wrangler d1 execute aggregator --command "ALTER TABLE sources ADD COLUMN pending_keywords_positive TEXT DEFAULT '';"
wrangler d1 execute aggregator --command "ALTER TABLE sources ADD COLUMN pending_keywords_negative TEXT DEFAULT '';"
wrangler d1 execute aggregator --command "ALTER TABLE logs ADD COLUMN post_text TEXT DEFAULT '';"
```

> اگر خطای "duplicate column" گرفتید، یعنی آن ستون از قبل وجود دارد — مشکلی نیست، عبور کنید.

### مرحله ۲: آپدیت wrangler.toml

دو تغییر در `wrangler.toml`:

**۱. اضافه کردن Workers AI binding:**
```toml
[ai]
binding = "AI"
```

**۲. اضافه کردن Cron جدید:**
```toml
[triggers]
crons = ["*/2 * * * *", "30 22 * * *", "30 23 * * *"]
```

| Cron | زمان ایران | کار |
|------|-----------|-----|
| `*/2 * * * *` | هر ۲ دقیقه | اسکن منظم |
| `30 22 * * *` | ۲ بامداد | تحلیل AI کلیدواژه |
| `30 23 * * *` | ۳ بامداد | گزارش روزانه |

### مرحله ۳: دیپلوی

```bash
wrangler deploy
```

### مرحله ۴: ثبت دستورات جدید

آدرس زیر را در مرورگر باز کنید:
```
https://<your-worker>.workers.dev/setup-commands
```

### مرحله ۵: تنظیم موضوع برای منابع موجود

برای منابعی که قبلاً اضافه کرده‌اید، موضوع تنظیم کنید:
```
/settopic → انتخاب منبع → وارد کردن موضوع
```

موضوع برای تحلیل AI ضروری است — بدون موضوع، AI کلیدواژه پیشنهاد نمی‌دهد.

## ⚠️ محدودیت Workers AI و راه‌حل

### محدودیت پلن رایگان:
- **۱۰,۰۰۰ Neuron در روز** (در پلن Free)
- هر تحلیل AI حدود ۳,۰۰۰-۵,۰۰۰ Neuron مصرف می‌کند
- گزارش روزانه حدود ۲,۰۰۰-۳,۰۰۰ Neuron
- **مجموع روزانه: ~۵,۰۰۰-۸,۰۰۰ Neuron** — در محدودیت رایگان

### اگر به لیمیت رسیدید:

**راه‌حل ۱: ارتقا به Workers Paid (توصیه شده)**
- فقط **$۵ در ماه**
- **۵۰ میلیون Neuron در ماه** (به‌جای ۱۰ هزار در روز)
- کافی برای صدها تحلیل در روز
```bash
wrangler plan workers_paid
```

**راه‌حل ۲: کاهش مصرف**
- تعداد پست‌های تحلیل‌شده را کم کنید (متغیر `AI_POSTS_COUNT` در worker.js — از ۳۰ به ۱۵ کاهش دهید)
- گزارش روزانه را غیرفعال کنید (cron `30 23 * * *` را از wrangler.toml حذف کنید)
- تحلیل AI را فقط دستی اجرا کنید (cron `30 22 * * *` را حذف کنید و از `/aianalyze` استفاده کنید)

**راه‌حل ۳: غیرفعال کردن کامل AI**
- بخش `[ai]` را از wrangler.toml حذف کنید
- ربات بدون AI کار می‌کند — فقط تحلیل کلیدواژه و گزارش هوشمند غیرفعال می‌شود
- اسکن و فیلتر معمول (forward/deep/viral) بدون تغییر کار می‌کند

### علائم رسیدن به لیمیت:
- خطای `AI: rate limit exceeded` در لاگ‌ها
- تحلیل AI ناموفق می‌شود ولی بقیه ربات عادی کار می‌کند
- ربات به‌صورت خودکار fallback می‌کند (گزارش بدون AI، لیست ساده)
